# 存储说明

在后台「存储空间」管理图片保存的位置。每个存储位置都有名称，可以有多个，并分别设置是否启用、谁能在上传时选择它、是否作为自动备份目标。

## 存储类型

| 类型 | 填写内容 | 说明 |
| --- | --- | --- |
| **Local / NAS** | 服务器上的绝对路径 | 读取最快。Docker 部署时该路径必须挂载进容器（相同路径）；二进制 + systemd 部署时需加入 `ReadWritePaths`。 |
| **S3 兼容** | Endpoint、Region、Bucket、Access Key、Secret Key、对象前缀 | AWS S3、Cloudflare R2、MinIO、Backblaze B2 等。自建 MinIO 一般开启 Path-style。 |
| **WebDAV** | WebDAV 目录地址、用户名、密码、子目录（可选） | Nextcloud / ownCloud、群晖 WebDAV Server、Alist、rclone serve webdav、坚果云等。 |

密钥和密码加密后保存在数据库中，加密密钥是安装时生成的（旧站为原 `JWT_SECRET`）。编辑存储时密钥留空表示保留原值。

### WebDAV 示例

- Nextcloud：`https://cloud.example.com/remote.php/dav/files/用户名/origin`，密码建议使用「设置 → 安全」生成的应用专用密码。
- 群晖：在套件中心启用 WebDAV Server，地址形如 `https://nas.example.com:5006/共享文件夹/origin`。
- Alist：`https://alist.example.com/dav/存储名/origin`。

Origin 会自动创建所需子目录（MKCOL），不会跟随重定向，避免把凭据发给其他地址。WebDAV 服务器在内网时也可以用 `http://`，但公网请务必使用 HTTPS。保存后点「测试连接」，会执行一次写入、读取校验和删除。

访问存放在 S3 或 WebDAV 上的图片时，Origin 先下载到本地读取缓存（`data/cache`，默认保留 30 天），之后直接从缓存返回；同一张图片的并发请求只回源一次。

## 默认位置与上传选择

- **默认上传位置**：在存储卡片上设为默认上传位置。用户组的上传策略可以跟随默认，或固定到某个存储。
- **上传可选范围**：仅管理员 / 登录用户 / 游客与登录用户。用户组还需要开启「允许自选开放存储」才会在上传界面出现选择。

## 自动备份与多地副本

开启某个存储的「自动备份」后，之后上传的每张图片都会异步复制到该位置，并做 SHA-256 校验；失败会退避重试，失败项可在「多地副本」中重试。对已有图片可以在存储卡片上「补齐历史」副本或「校验副本」。

读取时优先使用本地副本；本地文件丢失时会从其他健康副本恢复。迁移任务只补齐目标副本，**不会自动删除来源**。

存储位置一旦保存过图片，地址、目录、Bucket、前缀就不能再修改（避免已有图片失联）。要换位置，新增一个存储并补齐副本，再把默认位置切过去。

## 数据库备份

「存储 → MySQL 逻辑备份」可以手动或每日把数据库压缩备份到任一存储位置（包括 WebDAV）。备份包含账号和加密配置，**不包含图片文件、安装配置和密钥文件**，这些需要另外备份。备份目标必须私有。Docker 镜像自带 `mysqldump`；二进制部署需要服务器安装 MySQL 客户端。

## 旧版兼容存储

v0.4 之前的站点有两个名为「兼容存储」的位置，对应原来的 Local 与 S3 设置。它们保留旧图片的引用，不能删除，但可以照常作为默认位置或备份目标使用。
