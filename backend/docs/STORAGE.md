# 存储说明

Origin 的存储只有两个概念：

- **存储**：一个可以存放图片的位置——本地 / NAS 目录、S3 兼容 Bucket 或 WebDAV 目录。
- **副本**：某张图片在某个存储上的一份完整文件。一张图片可以有多份副本，任意一份可用就能访问。

后台「存储空间」管理存储，「后台任务」查看迁出、校验和备份的进度。

## 存储类型

| 类型 | 填写内容 | 说明 |
| --- | --- | --- |
| **Local / NAS** | 目录：绝对路径，或相对程序目录的路径（如 `data/uploads`） | 读取最快。Docker 中相对路径基于 `/app`；其他绝对路径必须挂载进容器的相同位置。二进制 + systemd 部署需把目录加入 `ReadWritePaths`。 |
| **S3 兼容** | Endpoint、Region、Bucket、Access Key、Secret Key、对象前缀 | AWS S3、Cloudflare R2、MinIO、Backblaze B2 等。自建 MinIO 一般开启 Path-style。 |
| **WebDAV** | 目录地址、用户名、密码、子目录（可选） | Nextcloud / ownCloud、群晖 WebDAV Server、Alist、rclone serve webdav、坚果云等。 |

密钥和密码加密后保存在数据库中。编辑时密钥留空表示保留原值。两个存储不能指向同一个位置（同一目录或同一 Bucket + 前缀），否则会互相覆盖、删除对方的文件。

存储上已经有副本后，它的位置（目录、Endpoint、Bucket、前缀）就不能再改。要换位置，新增一个存储，再按下文「移除存储」把旧的迁出。

### WebDAV 示例

- Nextcloud：`https://cloud.example.com/remote.php/dav/files/用户名/origin`，密码建议使用「设置 → 安全」生成的应用专用密码。
- 群晖：在套件中心启用 WebDAV Server，地址形如 `https://nas.example.com:5006/共享文件夹/origin`。
- Alist：`https://alist.example.com/dav/存储名/origin`。

Origin 会自动创建子目录，不跟随重定向（避免把凭据发给其他地址）。内网 WebDAV 可以用 `http://`，公网请使用 HTTPS。

## 每个存储的三个开关

| 开关 | 含义 |
| --- | --- |
| **默认上传** | 站点的默认上传位置，只能有一个。 |
| **可上传** | 允许作为上传位置。关闭后它只保存已有副本或备份，用户组也不能选择它。 |
| **自动备份** | 每张图片都复制一份到这里，包括开启前上传的旧图片（后台逐步补齐）。 |

另外还有「读取优先级」：数字越小越先读取。本地存储默认 10，远程默认 100。

## 用户组与上传位置

在「用户组」里为每个组设置：

- **默认上传位置**：跟随站点默认，或固定为某个存储。
- **成员可选择的存储**：勾选的存储会出现在上传页的选择框里。不勾选时成员只能用默认位置。

管理员总是可以选择所有「可上传」的存储。存储被暂停或关闭「可上传」后，会自动从所有用户组的可选范围里消失，不需要逐个修改用户组。

## 图片如何读取

访问一张图片时，按读取优先级尝试它的副本：

1. 本地副本直接返回。本地文件丢失时会记为「缺失」，并自动从其他副本恢复。
2. 远程副本（S3 / WebDAV）先下载到本地读取缓存（`data/cache`，默认保留 30 天），校验 SHA-256 后返回。同一张图片的并发请求只下载一次。
3. 所有远程副本都不可达、但缓存里还有旧文件时，直接返回缓存，不报错。

## 离线与自动恢复

每个存储都有自己的后台通道，负责复制、校验和删除文件，互不影响。

- 连续 3 次连接失败，存储被标记为**离线**，暂停访问 1 分钟。之后逐次加倍，最长 30 分钟，到期自动重试。
- 离线期间：读取会跳过它，改用其他副本；发往它的复制和删除排队等待，其他存储照常工作。
- 存储恢复后，排队的任务自动继续。也可以在卡片上点「重新检测」立即测试。

复制或校验失败的副本显示在「后台任务 → 副本异常」，会自动重试，也可以手动点「重试异常项」。

## 校验副本

在存储的编辑窗口点「校验副本」，会重新读取这个存储上的全部副本并比对 SHA-256。损坏或缺失的副本会自动从其他副本修复。进度在「后台任务」中查看。

## 移除存储

在存储的编辑窗口点「移除存储」，会先列出影响：有多少副本，以及多少张图片**只存在这里**。然后二选一：

- **迁出后移除（推荐）**：先把只存在这里的图片复制到你选择的存储，并校验完整性，全部完成后再移除。可以选择同时删除这个存储上的文件，不选则文件原样保留，只移除配置。
- **强制移除**：用于已经离线、无法再访问的存储。立即移除，不访问它。只存在这里的图片会移入回收站（它们已经没有可用的副本），回收站保留期满后彻底删除记录。存储上的文件不会被动。

默认上传位置不能移除，请先把默认位置切换到其他存储。移除时，用户组和数据库备份设置里对它的引用会被自动清除。

## 永久删除与清理

回收站到期或手动永久删除时，图片记录会立即删除；各存储上的文件交给后台按存储逐个删除。存储离线时，删除会等它恢复后再执行，不会卡住回收站。

## 数据库备份

「存储 → 运行设置 → MySQL 逻辑备份」可以手动或每日把数据库压缩备份到任一存储。备份包含账号和加密配置，**不包含图片文件、安装配置和密钥文件**，这些需要另外备份。备份目标必须私有。Docker 镜像自带 `mysqldump`；二进制部署需要服务器安装 MySQL 客户端。
