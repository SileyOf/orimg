# v0.5.1

审计与性能优化版。数据库结构仍为 9，没有新增迁移，配置文件、密钥、数据目录和图片链接均不变；从 v0.5.0 升级只需换镜像。

## 升级步骤（Docker）

1. 备份数据库与 `/app/data` 数据卷（常规备份即可，本版不改数据）。
2. 加载新镜像：`docker load -i origin-image.tar`，确认 `docker run --rm origin:0.5.1 -version` 输出 `v0.5.1`。
3. 将 Compose `.env` 中的 `ORIGIN_IMAGE` 改为 `origin:0.5.1`（未设置时默认已是 0.5.1），执行 `docker compose up -d`。
4. 检查 `/api/ready` 返回 200、登录、上传与旧图访问正常。

回退：停服后把 `ORIGIN_IMAGE` 改回 `origin:0.5.0` 再 `docker compose up -d` 即可，数据双向兼容。

## 行为变化

- 站点设置在进程内缓存最长 2 秒。通过后台修改设置会立即生效；直接改数据库或多实例部署时，其他实例最多延迟 2 秒看到变化。
- 新上传 JPEG 的缩略图会按 EXIF 方向旋转，与浏览器显示的原图一致；已有缩略图不会重新生成。数据库中记录的宽高仍是文件原始像素尺寸。
- 缩略图改用面积平均缩放，细节和文字更清晰，不再出现锯齿或摩尔纹。
- 上传时存储层失败只向客户端返回 `failed to store image`，详细原因写入容器日志。
