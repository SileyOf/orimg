# Origin 邮件功能设计

状态：v0.4.6 已实现邮箱注册、独立找回页、HTML/纯文本邮件和模板文字编辑。邮件与注册均默认关闭，管理员完成发信测试后才可启用。

v0.4.6 更新：

- 注册使用独立请求表，邮箱验证成功后才在事务内创建普通用户，绑定管理员指定的启用组。组与注册设置加锁复核，角色/组不接受客户端覆盖。
- 模板独立存储于 `mail_templates`，不参与 SMTP 配置指纹。主题、标题、正文、按钮和页脚可编辑，使用 html/template 转义，不提供任意 HTML 输入。
- 邮件使用 multipart/related + multipart/alternative，包含纯文本、HTML、内嵌 Logo PNG。站点默认强调色在入队时固定，已入队邮件不会被后续模板修改影响。
- 预览使用同一服务端渲染器，浏览器通过无脚本权限的 sandbox iframe 隔离展示。注册、找回页继承站点外观，不显示旧品牌占位内容。
- 注册、重设密码链接仅主动 POST 确认后消费；GET 访问与预览不触发发信或创建用户。

第一阶段与早期规划的差异（历史）：

- 配置表实际为 `mail_settings`，另有独立限流表 `mail_limits`。
- 邮件任务统一在邮件页筛选、取消及重试，不在后台任务页再重复一套入口。
- 发送速率、超时、保留期限使用固定保守值；不提供回复地址、可编辑模板或高级参数入口。
- 失败原因显示在记录表格中；记录仅表示服务器接收状态，未接入退信或送达回执。
- 一次性令牌位于 URL fragment，浏览器读取后清除地址片段；服务端数据库统一计算有效期，避免应用与 MySQL 时区差异。
- 更改连接参数须重新测试。投递内容加密保存，发送成功、取消或过期后清除；凭据使用原 JWT_SECRET 加密。
- 本轮隔离测试使用注入的假发信器，不会给克隆库真实用户发邮件。真实 SMTP 连通性和收件箱投递需管理员部署后主动测试。

下文保留设计依据和后续验收目标，不代表所有高级项已在本版开放。当前部署方式以 `README_DEPLOY.md` 为准。

## 第一版范围

1. 邮箱验证：账号设置显示未验证/已验证，支持重新发送。
2. 忘记密码：邮件中的一次性链接进入重设页面，完成后回到正常登录。
3. 修改邮箱：验证当前密码，先发送到新邮箱；验证成功才替换登录邮箱，同时通知旧邮箱。
4. 安全通知：密码重置、邮箱更换成功。
5. 管理后台独立「邮件」页；后台任务页可筛选邮件任务。

本期不做营销群发、邮件模板代码编辑或多供应商自动切换。SMTP 是第一种传输方式，接口保留未来接入服务商 HTTP API 的能力。

## 页面与交互

- 邮件页分为「发信设置」「模板预览」「发送记录」三个标签。
- 常用设置只显示启用开关、服务器、端口、TLS 模式、用户名、密码、发件人名称和地址。
- 高级项收起：回复地址、队列速率、超时、审计保留时间。
- 保存设置需要确认；保存和发送测试邮件是两个不同操作，保存不会发信。
- 测试邮件只发到管理员明确输入并确认的收件人，提供真实失败原因，凭据脱敏。
- 记录使用紧凑表格：时间、类型、脱敏收件人、状态、重试次数；失败详情进入侧栏。
- 状态区分「排队」「发送中」「服务商已接受」「失败」「过期」「取消」。SMTP 接受不代表已送达收件箱。
- 账号设置将邮箱验证与修改邮箱分开。验证链接失效时，可重新发送，不清空资料。
- 所有页面沿用当前强调色、深浅外观与按钮反馈。

## 身份验证安全

一次性随机令牌、到期失效、统一找回响应和限流采用 [OWASP 密码找回指南](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) 的基本原则。

- 令牌使用加密安全随机数，校验表只存哈希；绑定账号、用途和目标邮箱，不同用途不能互换。
- 建议初始值：找回链接 20 分钟、邮箱验证 24 小时、重发冷却 60 秒。属于产品默认值，可在实施时调整。
- 找回入口统一返回「如该邮箱已注册，将收到邮件」，避免透露用户存在性；异步投递并测试响应时间差。
- 同时限制 IP、账号、收件人和全站发送量。达到阈值可要求验证码，不能锁死正常账号。
- GET 打开链接只显示确认页，POST 才消费令牌；避免邮件安全扫描器提前用掉链接。
- 令牌消费、修改密码和增加会话版本在一个事务完成。不得自动登录，旧会话应失效。
- 密码找回后撤销旧 API Token，界面明确告知；不发送任何明文密码。
- 重置地址使用管理员确认的 HTTPS 安全域名，不直接信任请求 Host。图片复制链接仍可以跟随当前域名。
- 验证页面不放第三方脚本；设置 no-referrer；访问日志不记录令牌。
- 修改邮箱需要近期身份确认，参照 [OWASP 身份验证指南](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。旧邮箱在新邮箱验证成功前继续可用，账号邮箱唯一性在提交时再次检查。

## 队列与数据结构

建议新增版本化迁移，不复用图片副本队列：

| 表/字段 | 用途 |
| --- | --- |
| mail_profiles | SMTP 配置、TLS 策略、加密凭据、启用状态 |
| mail_outbox | 类型、收件人、加密投递内容、状态、下次执行时间、租约、重试次数、去重键 |
| account_challenges | user_id、用途、token_hash、目标邮箱、过期时间、已消费时间 |
| users.auth_version | 密码重置和敏感资料变更后的会话撤销 |

- 发信请求和 outbox 入队使用事务，Worker 领取带租约任务，重启后可继续。
- 使用至少一次投递，不承诺跨 SMTP 的严格「恰好一次」。固定 Message-ID 和去重键降低重复影响，一次性令牌保证重复邮件不能重复操作账号。
- 队列为了重试必须持有可发送令牌：短期加密保存，发送成功或过期后清除敏感内容；验证表仍只留哈希。
- 暂时性错误指数退避；认证失败或永久拒收不无限重试。链接过期后禁止发送旧链接。
- 设发送并发、每分钟上限、队列容量和最长保留时间。队列拥堵不阻塞上传。
- 邮件地址在普通日志中脱敏；密码、令牌、完整验证 URL 不进入日志和错误返回。
- TLS 强制验证证书，支持隐式 TLS 与 STARTTLS；协商失败不降级为明文。SMTP 主机只能由管理员配置，防止配置接口被滥用访问内网。

## 上线与兼容

- 默认关闭邮件。只有管理员保存配置、确认测试成功后才能开启正式发送。
- 现有 email_verified 状态原样保留，不把生产账号一律标记未验证，不因上线邮件而禁止现有账号登录或上传。
- 「未验证邮箱不能上传」如需要，应作为后续用户组独立开关，默认关闭，先通知现有用户。
- 增加 auth_version 时，明确旧 JWT 的过渡规则；不静默制造全员掉线。
- 准备本地 SMTP 捕获器测试环境，所有集成测试使用虚构邮箱，不向克隆库中的真实邮箱发信。
- 发送域名需要按供应商要求配置 SPF、DKIM、DMARC。验收包含投递成功、退信、限流、超时和证书错误，不只验证端口连通。

## 验收标准

- 两个并发请求使用同一令牌，仅一个成功；超时、已用、错用途令牌均失败。
- 未知邮箱与已知邮箱的公开响应一致；发送限流不影响正常图片上传。
- 邮箱更换失败或取消时保留原邮箱；新邮箱被抢先占用时事务失败，不覆盖他人账号。
- Worker 在领取、发送前、发送后崩溃均可恢复，记录不虚报「已送达」。
- 密钥不回显，导出日志不含令牌；预览与测试不会修改账号。
- 手机/桌面、浅色/深色的账号流程和错误状态完整测试。
