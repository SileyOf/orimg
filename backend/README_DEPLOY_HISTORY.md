# Origin v0.5.0 部署说明

## v0.5.0：首版 Docker

提供 x86_64 / ARM64 应用镜像离线包、已有数据库与可选 MySQL Compose 部署方式。镜像内置前端、证书、时区与 MySQL 备份客户端，默认非 root、只读根文件系统，数据单独持久化。详见 [Docker 部署指南](docs/DOCKER.md)。Docker 包不是原目录覆盖升级包，请不要将镜像包内容覆盖到二进制程序目录。

没有新增数据库结构迁移；v0.4.8 的历史密钥兼容处理保留。旧站点必须先备份并检查挂载、数据库地址及后台任务开关。

## v0.4.8：旧密钥升级兼容修复

修复 v0.4.7 对旧 JWT_SECRET 强度检查导致的启动失败。原密钥不变，旧加密配置不重写；弱密钥站点生成独立登录签名密钥并要求重新登录一次。没有新增数据库表或字段。

覆盖步骤及备份要求见 [v0.4.8 升级说明](docs/UPGRADE_v0.4.8.md)，发行压缩包内为 `UPGRADE.md`。请保留 `.env`、`data/` 和所有自定义图片/背景目录，不要用示例配置覆盖生产配置。

## v0.4.7：安全初始化与旧库接入

首次部署提供 `/install` 安装向导，配置数据库和初始管理员。接入旧库需验证原管理员和原密钥，保留账号、页面及存储设置；默认暂停后台任务。无默认密码，不再在启动时自动提升用户权限。

本版还加入显式代理信任、数据库 TLS、升级互斥锁、就绪检查、优雅退出、请求读取超时和缩略图解码预算；自定义背景/Logo 改为持久化保存。

**升级前务必阅读 [安装与旧库接入](docs/INSTALLATION.md)**：原密钥不能随意替换；反向代理必须配置 `TRUSTED_PROXIES`；需要保留原数据库和文件挂载。当前不是独立迁移工具，也还未发布 Docker 镜像。已有生产 `.env` 不应被示例配置覆盖。

下方历史说明如有冲突，以 v0.4.8 升级说明和安装文档为准。

## v0.4.6：邮箱注册、图文邮件与用户组编辑

- 找回密码独立为 `/forgot-password`，登录页仅保留入口，不再展开第二张表单。
- 邮箱注册入口为 `/register`，默认关闭。在「邮件 → 邮箱注册」启用，并选择一个启用中的用户组。要求正式发信已开启。
- 用户先填写邮箱并完成验证码，再通过邮件链接设置用户名、密码。邮箱验证前不会创建用户；创建后邮箱已验证、角色固定为普通用户，加入选定组并继承其容量和上传策略。
- 注册链接 24 小时有效且只能使用一次。关闭注册、删除/停用所选组后不会继续创建账号；改换注册组后旧组链接失效，需重新申请。链接只在主动提交后消费，邮件扫描器打开链接不会创建账号。
- 六种邮件支持 HTML 与纯文本双格式，Logo 以内嵌 PNG 发送并跟随站点默认强调色，不依赖外部图片请求。
- 「邮件 → 邮件模板」可编辑主题、标题、正文、按钮、页脚并预览。支持 `{{site_name}}`、`{{message}}` 两个文字变量。输入按纯文本处理；链接与有效期由系统追加，不能通过编辑文案替换。修改模板不影响 SMTP 测试状态，只应用到之后入队的邮件。
- 用户组卡片、列表、紧凑视图保留，编辑改为独立弹窗。关闭未保存表单有确认，保存中禁止重复提交；不会再把卡片展开为整页。

### 从 v0.4.5 升级

1. 备份数据库、程序和 `.env`，保留原 `JWT_SECRET`。合并覆盖程序和 `static`，不要删除已有自定义背景/Logo 或覆盖存储目录。
2. 首次启动自动执行迁移 9，新增 `mail_templates`、`registration_settings`、`registration_requests` 三张表及默认关闭的注册设置，需要 CREATE/INSERT 权限。不会修改旧账号、组策略、SMTP 配置、页面文案或图片。
3. 本次必须同时升级后端与静态文件，不能仅替换前端。无需重新填写 SMTP；默认不会开放注册或自动给旧用户发信。
4. 检查反向代理把 `/forgot-password`、`/register`、`/account-action` 交给 Go 服务，与原有 `/dashboard` 一致。
5. 在管理后台选择注册组，确认该组权限和容量后再启用。真实收件箱最终效果仍需部署后主动发送一封测试邮件确认。

数据库备份按整个数据库导出，因此自动包含新增表。备份仍需单独保管 `.env` / `JWT_SECRET` 和图片原文件。DDL 可能已提交后才报错，迁移支持重复执行，不要手工删除现有表来重试。

本版验证：Go 测试、HTML/MIME/图片和转义测试；授权测试库重复迁移与假发信器完整邮件/注册流程；390、768、1440、2560 宽度浏览器回归，含 30 个组、45 个存储位置。未连接生产库、真实 SMTP 或云存储。

## v0.4.5：邮件与备份整理

- 独立邮件页：SMTP 配置、测试发送、脱敏发送记录、取消/重试、固定模板预览。
- 默认关闭邮件。先保存关闭状态的配置，再发送测试邮件；邮件服务器接收成功后，才能开启正式发信。配置连接参数改变后需要重新测试。保存设置本身不会发邮件。
- 支持 TLS（通常 465）和 STARTTLS（通常 587），验证服务器证书，不降级到明文。认证支持 SMTP PLAIN；使用服务商提供的 SMTP 授权密码。仅支持公网 SMTP 地址，不接受内网、中转映射或元数据地址。
- 安全链接域名填写完整 HTTPS 根地址，例如 `https://img.example.com`。域名由管理员固定配置，不取请求 Host；无需改动图片的多域名链接机制。
- 账号设置增加邮箱验证、验证后更换邮箱；登录页增加找回密码。验证邮件 24 小时有效，重设密码链接 20 分钟有效，链接只在用户确认提交后消费。
- 换邮箱或修改/重设密码会撤销旧登录会话和 API Token。既有登录 JWT 默认版本为 0，升级本身不强制所有用户退出。原邮箱验证状态保持不变，未验证不会因本次升级被禁止上传。
- 邮件独立排队，固定 Message-ID、租约恢复、最多 5 次尝试、指数退避；成功/取消/过期清除加密投递内容，完成记录保留 30 天。SMTP 接收不代表送达收件箱，重试可能造成重复邮件，但验证操作不能重复执行。
- 发信上限 20 封/分钟，队列容量检查为 1000 条；账号和收件地址有重发冷却，另有 IP 与全站申请限流。第一版不提供群发、HTML 模板编辑、退信 Webhook 或 SMTP OAuth。
- 后台任务页移除第二套 Local/S3 补齐、同步方向及 Mirror 说明；保留已有任务历史和恢复操作。新的补齐/校验统一在存储页操作，邮件任务在邮件页查看。
- MySQL 备份可直接选择现有 Local/NAS 或 S3 兼容存储。不选新位置时仍使用原 S3，旧任务目标保持兼容。备份压缩包流式写入，不整包加载到内存。
- 数据库备份与副本工作器开关分离；全局 `DISABLE_BACKGROUND_WORK` 仍会停用全部后台工作。备份最多执行 30 分钟，异常中断超过 35 分钟后标记失败，可重新运行。重复新建会返回现有待执行任务。
- 修复旧备份记录显示「已完成但仍有 1 待处理」的问题，仅调整展示，不改写历史任务数据。

### 从 beta.4 升级

1. 先备份 MySQL、现有二进制、静态文件和 `.env`，保留 `JWT_SECRET`。数据库备份包含账号、头像和加密配置，但不包含图片原文件与 `.env`；图片需另外备份。
2. 停止程序，合并覆盖本版 `zhuapic`、`static` 和文档，不删除自定义 Logo/背景，不覆盖 `.env` 或存储目录。
3. 首次启动自动执行迁移 8：新增 `users.auth_version` 及 `mail_settings`、`mail_outbox`、`account_challenges`、`mail_limits` 四张表，需要 CREATE/ALTER 权限。不会重置旧账号、密码、页面配置、上传路径或图片。
4. 无 SMTP 配置时邮件保持关闭，不会自动向现有用户发送验证邮件。管理员自行填写服务商信息、确认测试收件人、测试后开启。
5. 按邮件服务商要求配置 SPF/DKIM/DMARC，检查真实收件箱及垃圾箱。本包的隔离测试不代表实际域名已具备邮件投递能力。

请不要只覆盖静态资源。回滚到不识别 `auth_version` 的旧版会失去会话撤销保护，需结合数据库备份与停机窗口处理。下一版再统一用户、用户组和存储的权限描述，本版不改动它们的策略含义。

## beta.4：用户组权限与账号资料

- 用户组独立设置默认存储和「允许自选开放存储」。管理员上传也使用所属组默认值，不再绕开组设置。
- 默认存储：用户组指定位置优先，选择「跟随站点」才使用全站默认。明确分配的默认位置不受存储「用户可选」限制。
- 额外可选位置：必须同时允许组内自选，并符合存储开放范围；普通用户只看到已向登录用户/游客开放的位置，管理员可选管理范围内的位置。关闭组内自选后，任何角色都只能用组默认位置。
- 所有用户组均可增删改。删除组会把成员设为未分组，保留账号、图片、管理员身份；未分组无法上传。组被删后不会自动重建或按角色回退。
- 游客在用户组页明确指定一个组；不指定、组被删除或策略停用即不可上传。原游客组在升级时按 ID 绑定，原名称不变。
- 管理员可为单个用户设定「跟随用户组 / 自定义容量 / 不限容量」。降低配额不删除已有图片；超过配额时停止新上传。
- 头像在账号设置更换/移除，浏览器居中裁剪为 256px，服务端验证并重新编码，去除附加元数据。头像跟随正常数据库备份，不写入 static 或图片存储目录。
- 并发上传先预留个人容量，完成或失败后释放；崩溃遗留预留最多一小时后失效。单次上传最长 15 分钟，避免无限占用。
- 邮件功能仅提供设计文档 `docs/MAIL_DESIGN.md`，没有启用 SMTP、发送邮件或修改现有邮箱验证状态。

### 升级注意

本版含第 7 项数据库迁移，不能只替换 static。先备份数据库，再停止旧程序、覆盖后端程序与 static、启动新版。
首次启动需要 CREATE/ALTER 权限，新增三个字段及两张表；保留既有账号、密码、存储配置和图片数据。
MySQL DDL 不保证整组事务回滚；迁移支持重复执行，启动失败时先排查权限/日志，不要手动删除原表。
新表为 `user_avatars`、`upload_reservations`，原 `user_groups.is_system` 仅保留兼容列，不再限制任何组。
请勿覆盖 `.env`、`data` 或其他存储目录。压缩包不包含这些文件。
升级后检查游客组绑定和各组自选开关：旧固定位置策略默认不允许自选，旧跟随站点策略保留允许自选。
不建议直接回滚旧二进制：旧版缺少未分组禁传规则，也不识别个人容量与自选开关；如需回滚应同时恢复升级前数据库备份。

## beta.3：缓存可见与多视图管理

- 存储页上方独立显示 S3 本地读取缓存：目录、缓存文件数与大小、过期待清理量、保留时间、自动清理周期。缓存不计入永久副本，可展开查看最大的 20 个缓存文件及过期时间。
- 统计仅扫描缓存根目录内符合图片缓存命名规则的普通文件，不递归备份/临时目录、不跟随文件符号链接，也不下载云端原图。单次最多扫描 10 万个目录项，扫描循环限制约 2 秒；结果缓存 30 秒。达到上限会标记部分统计，数值为下限，而不是冒充完整容量。

- 用户组先呈现成员、上传额度、固定存储、启用状态；展开时才创建编辑表单。切换视图和搜索不丢弃未保存的表单输入，保存仍需二次确认。

## v0.4 存储升级

从 v0.3 升级包含数据库增量迁移 5、6。新增 `storage_targets` 和 `storage_target_replicas`，保留原有图片、Local/S3 副本、账号及页面设置，不搬运旧文件，不改变图片 URL。首次升级自动建立 Local、S3 两个存储入口，仍读取原配置。新存储位置固定，凭据可以轮换，密钥继续使用原 `JWT_SECRET` 加密。

### 部署到 aaPanel

1. 先停止进程并备份 MySQL、现有程序、`static` 和 `.env`。尤其保留原 `JWT_SECRET`，否则无法解密存储密钥。
2. 将升级包中的 `zhuapic` 和 `static/` 按文件合并覆盖到原程序目录。不要删除旧 `static/assets/site-background-*` 和自定义 Logo；不要覆盖 `.env`、`data/`、挂载目录或云端桶。
3. `chmod +x zhuapic` 后启动，检查日志中的迁移结果和图片访问。数据库账号需有建表、ALTER、索引、外键引用权限。迁移不会触发历史补齐，也不会默认启用新备份。
4. 在“存储”添加目标。Local 使用专用绝对目录；NAS/NFS/SMB 需先由系统挂载，再填写挂载目录。运行用户须有目录读写权限，挂载未就绪不要启用该位置。
5. S3 兼容服务填写实际 Endpoint、Region、Bucket 和凭据。保存后可在编辑弹窗执行“测试连接”，它只创建随机小文件、读回校验并清理；不会扫描或删除桶内原文件。
6. 选择默认上传位置，按需开启各目标的“自动备份”。若要同步旧图，另行点击“补齐历史”，操作前会确认流量与容量影响。

本包为 Linux amd64 静态二进制。若服务器为 ARM64，需要重新构建，不能直接使用此二进制。

### 存储行为

- **默认上传**：仅影响跟随站点策略的新图片。用户可在上传页选择管理员授权的位置，管理员可选全部可用位置；固定存储的用户组仍遵循原策略。
- **自动备份**：新图片先在主存储写入成功，再进入持久化副本队列。每个目标独立复制、读回并校验 SHA-256。主上传成功不代表所有备份已完成。
- **补齐历史**：为未删除图片建立缺失副本任务。重复点击不会重复建立同一图片/目标记录；源文件保留，不改变主位置或链接。
- **故障与重试**：失败项间隔 5 分钟重试，最多尝试 8 次，之后可人工重试。处理中断由租约回收；暂停存储会停止领取该目标的新任务，正在进行的传输可完成。关闭“自动备份”不取消已排队任务。
- **读取**：保留旧图片链路，新存储图片优先读取主副本，主位置不可达时尝试完整备份。读取会使用现有本地缓存目录；缓存与持久副本不是同一个目录。
- **删除**：有图片或任务引用的存储不能删除。旧 Local/S3 入口为兼容引用保留。图片进入回收站不会立刻删除副本；过期或手动彻底删除会清理所有已记录副本。这是多地同步副本，不是保留历史版本的独立灾备；建议云端另开版本管理/不可变备份。
- **界面**：存储页按独立位置显示副本数量、容量、待同步和失败数；后台任务页显示目标和文件级错误。图库和仪表盘包含新副本状态。侧栏不再显示固定 BASE 地址。

本版实现 Local 和 S3 两种读写适配器，并提供 R2、MinIO、Backblaze B2 的 S3 兼容配置预设，不包含 FTP/WebDAV/厂商私有 API。服务差异以官方文档为准：[R2 S3 API](https://developers.cloudflare.com/r2/api/s3/api/)、[MinIO S3 兼容性](https://min.io/product/s3-compatibility)、[Backblaze B2 S3 API](https://www.backblaze.com/docs/en/cloud-storage-call-the-s3-compatible-api)。本次使用模拟 S3 验证协议链路，没有使用真实云端凭据做写入测试。

### 验证与回滚边界

- 已在授权的测试库执行迁移及重复执行验证，核对原设置、账号、图片和旧副本记录未变。文件测试只使用临时本地目录、本机模拟 S3；测试记录结束后清理。历史补齐只验证任务生成，没有读取导入的原图。
- `DISABLE_BACKGROUND_WORK=true` 可暂停当前进程的所有自动后台工作，包括过期图片处理、清理、旧版备份任务和新副本队列；这不会修改数据库设置。它不是只读模式，手动 API 仍可写入。测试生产导出的数据库时不要启动默认工作器，也不要点击真实存储连接测试。
- **启用新主存储后不能仅覆盖回旧版二进制**：旧版不认识新目标引用。升级后尚未使用新存储时可恢复升级前程序与数据库备份；使用后应保留 v0.4 服务，或先安排数据迁移，不得直接降级导致新增图片不可达。

## 存储策略

- `Local`：只保存本地原图。
- `S3`：只保存 S3 原图，本地仍是按 TTL 清理的读取缓存。
- `Mirror`：先原子写入永久本地副本，再由后台工作器异步复制到 S3。

Mirror 图片优先从本地输出。本地副本丢失时会从健康 S3 副本回源并自动修复。S3 同步失败会进入退避重试队列，不会让已经成功写入本地的上传失败。

后台“后台任务”页可以执行：

- “补齐 Local”：从 S3 复制本地缺失的永久副本，S3 原文件保留。
- “补齐 S3”：从 Local 复制云端缺失的副本，本地原文件保留。
- “校验现有副本”：对 Local/S3 文件执行 SHA-256 完整性校验，不复制也不删除。
- 暂停、继续和重试失败任务。

副本同步始终保留来源副本，不会自动删除原文件。旧图片的兼容主存储字段不被改写，因此紧急回滚 v0.2 二进制时仍能按原 Local/S3 方式读取；v0.3 新表和可空字段会保留但不会影响 v0.2 查询。

## 回收站

删除图片后会立即停止公开访问，默认 7 天后才删除 Local、S3、缓存和缩略图。管理员可以在独立回收站恢复图片或立即永久删除。物理删除失败会延迟重试，不会直接丢弃数据库记录。

## MySQL 备份

管理后台支持手动或每日将 MySQL 逻辑备份压缩后上传到 S3，默认关闭。启用前确认服务器已安装 `mysqldump`，并在后台填写可执行文件路径和 S3 备份前缀。

数据库密码只通过子进程环境变量传递，不会出现在命令行参数中。建议同时在 S3 控制台为备份前缀配置 14 至 30 天生命周期。请保持 `.env` 中 `JWT_SECRET` 稳定；后台下一次保存的 S3 Secret 会使用它派生密钥进行 AES-GCM 加密。

## MySQL 性能配置

当前版本继续使用 MySQL。图片二进制不写数据库，数据库主要保存账号、图片元数据、策略、用量、审计和任务状态；配合复合索引以及图片、用户、审计的游标分页，不需要为了本阶段流量迁移 PostgreSQL。

推荐先使用以下连接池参数，再根据 MySQL `max_connections` 和应用实例数调整：

```env
DB_MAX_OPEN_CONNS=30
DB_MAX_IDLE_CONNS=10
DB_CONN_MAX_LIFETIME=30m
```

所有应用实例的 `DB_MAX_OPEN_CONNS` 总和建议不超过数据库可用连接数的 60%。用户量增长后优先增加慢查询监控、独立 Redis 限流和任务工作器，再评估数据库迁移。应用与 MySQL 跨公网部署会明显放大控制台首次加载时间，生产环境建议同区域内网连接并启用 TLS。

4. 在“后台任务”先执行“校验现有副本”，再按需要补齐 Local 或 S3 副本。
5. 确认 S3 配置可用后，再把默认存储或指定用户组改为 `mirror`。
6. 磁盘停止线默认 85%；达到阈值后 Local/Mirror 新上传会被拒绝，S3-only 不受影响。
7. 打开“审计日志”，确认登录事件可见；普通账号按需创建 API Token 并用测试图片验证后再接入 PicGo/ShareX。

## 多域名与 CDN

“页面与安全”的站点域名白名单支持多个域名，例如 `img.example.com,pic.example.com`。上传返回、相册和复制代码采用用户当前访问的白名单域名。反向代理必须保留原始 `Host`，并设置 `X-Forwarded-Proto: https`。

建议 CDN：

- `/assets/*`：版本化静态资源，可长期缓存。
- `/i/*`、`/t/*`：随机不可变文件名，可长期缓存。
- `/api/*`、管理后台和用户后台：不缓存。
- 回源保留 `Host`，启用 HTTPS，并对 `/i/*` 设置合理的防刷频率。

## aaPanel 需要覆盖的文件

- `zhuapic`：Linux amd64 静态后端二进制。
- `static/`：完整前端目录。

不要覆盖：

- `.env`
- `data/`
- 自定义上传目录、缓存目录和缩略图目录

推荐目录：

```text
/www/wwwroot/img.example.com/
  zhuapic
  .env
  static/
  data/
```

进程工作目录必须是二进制所在目录：

```bash
chmod +x zhuapic
./zhuapic
```
